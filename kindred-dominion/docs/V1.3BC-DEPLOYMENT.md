# Isolated home-server deployment preparation

The Docker files are prepared for a later **owner-authorized** installation. This stage did not install or run anything on the home server and changed no proxy, firewall, PostgreSQL configuration or other application.

**Docker execution remains pending owner validation.** This Windows machine has neither Docker nor WSL; the owner explicitly selected “Leave Docker execution pending for owner validation.” Windows production compilation, player-artifact checks and actual browser tests are separate evidence and do not establish container startup/health success.

## What is packaged

The multi-stage `Dockerfile` installs exact lockfile dependencies using `npm ci --include=dev`, validates content/assets, runs strict TypeScript and builds `dist-player`. The final image contains only the player static output and an unprivileged NGINX configuration. It runs as UID/GID 101, listens on container port 8080, has an HTTP health check, and can use a read-only root filesystem with temporary files under `/tmp`.

Studio, simulation workers, laboratory/demo fixtures, original artwork masters, source files and unpublished creature images are excluded. The default player pack is the 150 owner-designed cards with placeholders. Only the existing neutral UI crest/fallback are permitted testing-level asset exceptions. A later committed owner artwork release can be selected explicitly with `KINDRED_CONTENT_ID`; referenced creature images must be approved for production sharing. Local/base64 artwork is rejected. No separate image migration or external image host is needed.

Pinning avoids mutable-tag drift; review and revalidate image updates. The official [Node image index](https://raw.githubusercontent.com/docker-library/official-images/master/library/node) and [NGINX unprivileged documentation](https://github.com/nginx/docker-nginx-unprivileged/blob/main/README.md) describe the image families. The latter uses port 8080 and `/tmp` paths; its current image namespace is `nginx/nginx-unprivileged`.

Vite normally copies its whole public directory, so the player build instead emits an approved asset list. See [Vite asset handling](https://vite.dev/guide/assets.html). The Git-tracking check runs in the source checkout. The Docker builder's explicit source-archive mode cannot inspect a Git index because `.git` is deliberately excluded from the context; the deployment preflight therefore requires a clean checkout.

## Future first installation

These commands are instructions, not actions performed by this stage. Use a Docker-capable Ubuntu host after installation authorization. Prefer a supported current Docker Engine/Compose release. Docker documents a localhost-publication isolation caveat in Engine versions older than 28.0.0; see [published port behavior](https://docs.docker.com/engine/network/port-publishing/).

Clone into a dedicated directory and select the reviewed commit/tag:

```sh
git clone https://github.com/Revty79/kindereddominion.git kindred-dominion-checkout
cd kindred-dominion-checkout/kindred-dominion
git checkout --detach <approved-commit-or-tag>
git status --short
docker version
docker compose version
ss -ltn
```

The working tree must be clean. Choose an **unused** host port after inspecting listeners; 18083 below is only an example. Do not stop an existing service to obtain it. Binding stays on loopback in this preparation stage.

```sh
export KINDRED_PORT=18083
export KINDRED_BIND=127.0.0.1
export KINDRED_REVISION="$(git rev-parse HEAD)"
export KINDRED_CONTENT_ID=founding-kindreds-owner-v1
docker compose config --quiet
docker compose build --pull
docker compose up -d --wait
docker compose ps
curl --fail "http://127.0.0.1:${KINDRED_PORT}/healthz"
curl --fail "http://127.0.0.1:${KINDRED_PORT}/"
```

Compose uses the distinct `kindred-dominion` project and its own default network. It does not attach to Serrian Tide, create a PostgreSQL service or mount another application's storage. No persistent server volume is required for this static phase. NGINX blocks source/private paths and serves missing assets as 404. HTML is revalidated; static assets have a bounded cache lifetime.

No reverse-proxy, firewall, VPN or public-access commands are included. Friends can access a hosted address only after the owner separately approves the server installation and access route. Keep testing private until then.

## Pending disposable Docker acceptance

On an authorized disposable Docker machine, choose a separate unused loopback port and run:

```sh
export KINDRED_PORT=18084
sh scripts/check-docker.sh
```

The script requires a clean checkout, builds the pinned image, starts an isolated acceptance project, checks health, HTTP serving, non-root execution, excluded source/master directories, absence of the temporary card image, and restart behavior. It deliberately leaves the acceptance server available for browser validation. The script prints the exact project-specific shutdown command.

With dependencies/Chromium available on the test runner, point the actual player browser cases at that host/port:

```sh
KINDRED_PLAYER_URL=http://127.0.0.1:18084/ node node_modules/@playwright/test/cli.js test tests/browser/owner.spec.ts --grep "invited player build"
```

Record the Git revision, image ID/digests, Compose version, configured bind/port, health result, non-root UID, browser result and clean Git status. Do not mark this gate passed merely because the static Windows build succeeded.

## Stop and inspect

For the normal project, with the same revision/port environment:

```sh
docker compose logs --tail=100 game
docker compose stop
docker compose start --wait
docker compose down
```

These target the Kindred project only. There are no server player volumes in this phase, and browser data is not deleted by stopping containers. For the disposable acceptance project, use its printed `docker compose -p …` command instead of the normal project's commands.

## Update and rollback

Record the current image/commit and retain that image. Fetch reviewed source without overwriting local work:

```sh
git status --short
git fetch --tags origin
git checkout --detach <new-reviewed-commit>
export KINDRED_REVISION="$(git rev-parse HEAD)"
docker compose config --quiet
docker compose build --pull
docker compose up -d --wait
docker compose ps
```

Re-run health and browser acceptance before treating the update as accepted. Keep the same browser origin to retain local saves. A new content version applies to new matches; existing saved matches retain their own definitions.

For a subsequent release rollback, select the previous **compatible player** image already retained locally:

```sh
export KINDRED_REVISION=<previous-compatible-commit>
docker compose up -d --no-build --wait
```

Verify health and read a saved match. Do not roll an owner-engine 1.3.1 save back to an executable that cannot understand its content; keep its backup rather than clearing storage. For the first installation, rollback is stopping/removing the new Kindred stack. There is no authorization to change another application's deployment.

Future database-backed releases need a separately approved migration/backup/restore plan and schema-compatible rollback; see [permanent storage](V1.3BC-STORAGE.md). Do not add a live database to this static deployment by inference.
