# V1.3A owner guide

V1.3A adds a reusable mechanics engine and form controls. Your original 30 cards, complete 150-card comparison library, decks and artwork remain available. Existing working drafts, selected versions and saved matches are preserved. The laboratory is additional development content; it is not automatically activated and is not the final commercial collection.

## Start

Double-click `Start Kindred Dominion.cmd`, or run:

```powershell
cd D:\kindereddominion\kindred-dominion
npm run dev
```

Open **http://127.0.0.1:5173/**. Keep the terminal open. Ctrl+C stops it. A fresh checkout needs `npm ci`; the launcher does that when dependencies are absent. No account, database server or external AI service is required.

Before significant design work, download **Developer Studio → Content Versions and Backups → Export complete Studio backup**. Browser-local content needs that independent backup.

## Start with a prepared experiment

Open **Battlefield Sandbox → Load saved scenario**. Thirty LAB scenarios are supplied. Selecting one copies its immutable definitions and prepared state into the sandbox; it does not replace your working draft or active ordinary match.

Useful first experiments:

| Scenario | Action and observation |
|---|---|
| Continuous enhancement — remove its source | Inspect the Wolf, execute Dismiss at an empty friendly position, and observe the aura disappear without changing its permanent modifier. |
| Continuous weakening — remove its source | Dismiss removes the enemy Basilisk; its orthogonally adjacent victim regains power. |
| Dynamic friendly population | Place another Wolf and inspect the Alpha's separate dynamic contribution. |
| Enhanced / weakened census | Compare pre-dynamic classification with final effective power. |
| Reactive weakening chain | Bruise weakens allies and Chorus reacts once per turn. |
| First enhancement and a multi-step chain | Gift enhances Firstlight, which permanently enhances adjacent allies once. |
| False-to-true threshold | Gift crosses the Sentry condition; remaining above it does not repeatedly fire. |
| Captured variable sacrifice power | Replace the enhanced Wolf with Flytrap; its bonus uses the frozen sacrifice power divided by two, rounded down. |
| Conditional protection disappears | Rust reduces Ward's fortification; adjacent protection disappears immediately. |
| Destruction history and immutable power | Reaper destroys an enemy; inspect captured power and Scavenger's historical scaling. |
| Captured / lost territory reactions | Player Two places at A5 to capture A4; Border reacts to the actual friendly loss. |
| Row-winning / battlefield-position score | Expand Score breakdown to separate row points and card bonuses. |
| Incoming replacement context | Sacrificed Offering targets the actual incoming replacement. |
| Destroyed / sacrificed context after resurrection | The departed instance resurrects, then a later effect targets that exact identity. |
| Combined AND / NOT conditions | A second friendly creature makes a structured condition true. |
| Branching / multi-stage evolution | Evolve Wolf into Star Wolf and then Imperial Wolf; previous passive rules do not stay active. |
| Draw and generation events | Generator produces real cards and Scribe reacts to successful events. |
| Opt-in dynamic power reaction | The source explicitly reacts to actual dynamic changes rather than unchanged recalculations. |

Click **Execute scenario**, select the prepared hand card, click a legal position, then confirm **Execute placement**. Standard cards require an empty friendly cell; replacement/evolution must use the prepared predecessor's cell. Scenario descriptions explain the intended experiment. Execution uses normal engine resolution.

**Edit construction** unlocks setup; **Reset execution** returns to the original construction. Save or duplicate explicitly before changing a prepared scenario. Altering its copy does not rewrite the bundled version or any existing replay.

## Inspect why power or score changed

**Inspect effective-power instance** remains available during execution. Select a live or departed instance, or click an occupied cell when no hand placement is selected. The breakdown shows:

- Printed base; permanent enhancement/weakening and net modifier.
- Live aura contributions, with source creatures and rule identifiers.
- Power before dynamic scaling and each dynamic contribution.
- Permanent versus continuously granted protection.
- Final effective power.

Construction's **Intrinsic creature power (base plus permanent)** edits only that layer. Auras and dynamic bonuses are calculated, not manually painted into it. A net-only old snapshot cannot invent prior enhancement/weakening applications; the inspector identifies that case.

Expand **Score breakdown** for winning-row points, tactical ruleset points, card bonuses and final totals. Bonuses never change which row originally won. A negative calculated bonus contributes zero.

The **Ability resolution inspector** contains actual recorded snapshots, conditions, targets, protection/limit decisions, immutable event participants and power-change components. Select a snapshot to inspect it read-only; return to **Show committed state** before another action. A change record uses the actual prior/new effective power, with numerical permanent/aura/dynamic components. Unchanged power does not produce a successful-change reaction.

## Edit laboratory cards or create your own

To use the laboratory as a design starting point, open **Content Versions and Backups**, find **V1.3A · mechanics laboratory**, and choose **Restore as new draft**. Restoration first retains an automatic recovery draft. It does not activate the restored version for ordinary games. The saved lab, original 30 and provisional 150 remain separate.

Create/Duplicate/Edit cards in Card Library. Permanent identifiers stay fixed; duplicate when you need a new identity. Ordinary properties, influence, prerequisites, copy limits, artwork and metadata retain their existing forms.

### Continuous enhancement and weakening

In **Continuous, dynamic and scoring mechanics**, click **Add continuous effect**. Select Continuous power, choose targets, and set a positive or negative amount. All eight neighbors, orthogonal/diagonal neighbors, rows, columns, relative patterns and full-board selection are available. Relationship, classifications, Kindreds, exact definitions, territory, occupancy, ranges and source exclusion refine the group.

Use **Continuous activation condition** for additional requirements. The grant disappears when its source/condition/target stops qualifying; it is not permanent power. New eligible creatures receive the grant automatically.

Continuous eligibility uses intrinsic power. Dynamic scaling uses power after auras but before scaling. Final-power reads that would introduce recursive calculations are rejected. The editor explains these layers; choose the permitted named values rather than trying to build an equilibrium formula.

### Dynamic power

Click **Add dynamic scaling**. Choose a battlefield aggregate, historical counter, stack depth or supported arithmetic. For example, count friendly Wolves excluding the source, multiply by two and clamp the result to 0–6. Its bonus shrinks when those Wolves leave. Enhanced/weakened filters use power before dynamic scaling, preventing recursive classification.

Aggregates can count creatures/positions, sum tokens/fortification, or sum eligible permitted-layer power. Territory ownership, empty/occupied positions and row/column selectors support territorial designs. Multiple independent scaling entries add.

### Reactive abilities and thresholds

In **Ability builder**, select a supported trigger and one or more ordered effects. Open **Reactive relationship, cause and power-change filters** to restrict event ownership, classifications, definitions, Kindreds and causes.

For “another friendly creature is weakened → source gains one power, once per turn,” select **Other creature weakened**, Friendly event relationship, a self-targeted +1 power effect and Maximum per turn = 1.

Enhancement/weakening defaults to explicit permanent changes. Check aura/dynamic kinds when that reaction is intentional. Power-crossing triggers default to all actual power changes. First-change triggers retain match/lineage history. A protected or capped attempted effect does not manufacture a successful change.

Select **Condition becomes true** for a stored false-to-true transition, or **Source crosses power threshold** for up/down/either crossings. These default to once per match. Check the repeatable option only when later crossings should activate again; per-event/turn/match limits and causal safeguards still apply.

Conditions support numerical comparisons, source position, population, event ownership, source/selected-creature evolution stages, AND, OR and NOT. Presence tests use a filtered count compared with one. No source code or arbitrary formula is needed.

### Variable sacrifice or destruction power

For a Flytrap-style replacement:

1. Choose Replacement placement type and any desired prerequisites.
2. Add an On replacement ability with a Power effect targeting Source creature.
3. Change its magnitude expression to Divide by constant.
4. Set Input amount to Named numerical value → Captured sacrificed creature power.
5. Set constant 2 and rounding floor.
6. Save, checkpoint and test in a controlled replacement scenario.

Captured destruction, sacrifice and incoming context stays immutable after removal. Current/effective source and target values, base power, pre-dynamic values, history and stack depth have separate selectors. Missing event-specific values are zero. For a departed participant, the event record—not an unrelated creature now on the square—is the context.

### Conditional protection and scoring

Choose Continuous protection to grant destruction or weakening immunity, then configure its condition and target group. The grant is listed separately from permanent statuses and disappears with its source/condition. It does not prevent sacrifice, evolution, return, banishment or losing a positive aura.

Click **Add scoring bonus**. Choose Source survives, Source horizontal row is won, or Source vertical column has greater effective power. Combine numerical magnitude/caps with position, population, territory, history or other supported conditions. Points remain separate from ordinary row power in both Classic and Domination.

## Test decks, simulation and replay

The laboratory supplies four valid 15-card decks: **Auras and populations**, **Reactions and transitions**, **Sacrifice and history**, and **Protection and scoring**. Select the lab version directly in Match Simulator without replacing your draft. Both 3×5 and experimental 4×8 rules are available, each with Classic/Domination. These remain the existing scoring systems.

Choose a deterministic seed, two decks or round robin, mirrored seats and a match count. Work runs in a worker. Cancellation preserves partial results. Faults, invariants and action-ceiling timeouts are separate from legitimate results. The one-ply opponent is unchanged; results are engineering evidence, not commercial balance proof.

For ordinary play, explicitly activate a legal saved testing version. Return to game and choose its decks. Finished advanced matches are recorded with engine 1.3.0, immutable definitions, artwork and action signatures. Replay navigation and power inspection do not mutate the original match. V1.1/V1.2 versions remain available for explicit reactivation.

Reproduce the large validation runs with:

```powershell
node scripts/validate-v1.3a.mjs --regression
node scripts/validate-v1.3a.mjs --laboratory
```

The regression command compares all 4,720 preserved V1.2 matches against their saved digests/statistics. The laboratory command runs 1,200 matches across scoring, fields, Standard/Free and extreme duplicate configurations. Concise results go to `docs/v1.3a/`; full sampled/failure records go to ignored `.local/v1.3a/`.

## Save, publish, restore and recover

Saving a card changes a working draft. Checkpoints, approval and activating a version remain explicit. Adding advanced mechanics upgrades that draft to content schema 2 / engine 1.3.0; immutable older versions are not rewritten.

Complete backups retain working content, versions, scenarios, reports, replays and experimental artwork. A backup with any advanced entities declares engine 1.3.0 even when its working draft is still V1.2. Older executables reject it rather than silently dropping features. The new reader still supports old backups and verified legacy replays. Imports validate the whole candidate before an atomic transaction; review conflicts before replacement.

The [artwork publication process](V1.2-ARTWORK.md) remains available for both content schemas. Experimental images stay local until explicitly approved/exported. Published definitions use stable portable references; optimized WebP and original masters remain separate. Nothing in V1.3A creates final illustrations or automatically publishes drafts.

If browser storage rejects installing new bundled content, the loaded prior workspace remains available with an error banner; export a complete backup before retrying. No browser content is cleared. Concurrent stale-tab edits continue to fail rather than overwrite another tab. Keep one editing tab.

An advanced engine fault rolls back that action, halts without a competitive result and leaves readable diagnostics. Preserve its seed/configuration and exported record. Generation, resurrection, power, history, transition, causal-chain and resolution safeguards remain active in Free Play.

The authoritative [Master Card Mechanics](MASTER-CARD-MECHANICS.md) gives exact behavior and limits. Owner review remains necessary before V1.3B, final commercial card design, balance changes, artwork approval or deployment.
