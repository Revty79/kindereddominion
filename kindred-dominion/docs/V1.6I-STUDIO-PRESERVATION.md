## Updated architecture and compatibility

The original Studio modules remain. Sandbox execution now uses the player `PersistentGame`, input controller, preview/rendering, resolution/history and preferences through an explicit `BattleConnectionContext`. Ordinary battles retain the account API and server authority; laboratory execution uses a closed local adapter. Its construction/diagnostic board is retained for authoring and captured-state inspection. Details are in [Battle Laboratory](V1.6I-BATTLE-LABORATORY.md).

Optional laboratory metadata and a private ruleset revision ledger extend the existing workspace JSON. Old saved versions, unpublished cards, scenarios and replays remain readable. The immutable V1.1 baseline remains exact. Complete backups and existing server revision history remain available, and restoring old drafts preserves the new publication ledger. No SQL migration, player backfill, artwork import or configuration reactivation is required.

Confirmed integration corrections include the sandbox's secondary placement step, the deck tester overriding a selected Free Play rule with Standard, an initial empty-resolution guard in the shared viewer, ambiguous pending scenario/replay save feedback, and navigating to a scenario before a rule save was acknowledged. Pending content saves now hold Studio navigation; a delayed-response browser regression covers that transition. Consequential production confirmations and all gameplay/card/balance decisions remain unchanged.

## Administration and release

For local testing with existing secure configuration:

```powershell
cd D:/kindereddominion/kindred-dominion
npm run backend:build
npm run build:control
npm run dev:all
```

Sign in using an account with existing trusted developer/administrator authorization, then open the protected Studio. No unauthenticated role-creation endpoint is introduced. Tests use registered disposable PostgreSQL and dedicated ports 3130/5301; normal DEV ports, hosted TEST and live payments are untouched.

Reproduction of the new compiled acceptance requires the established registered-disposable environment and compiled backend/player/control output:

```powershell
npx tsx scripts/validate-v16-browser.mts --env <registered-disposable-env> --only=studio-laboratory
```

The existing TEST operator remains owner-controlled:

```bash
sudo kindred-update
```

No workflow trust root, operator installation protocol, production restriction, backup, restoration rehearsal or recovery safeguard is changed. The validated V1.6H checkpoint remains in history. Unfinished development stays in the isolated worktree until validation completes; publication must pass exact-commit CI before TEST eligibility.

Remaining human acceptance includes original-tool familiarity, comfortable navigation between construction and shared play, actual phone/tablet controls, animation pacing, dense large-board performance and strategic balance. Screenshots and deterministic tests do not establish those approvals. See [tactical rulesets](V1.6I-TACTICAL-RULESETS.md) for current limits and the V1.7 dependency assessment.
