# Kindred Dominion — V1.6C
## Interactive Card Selection, Dragging and Battlefield Placement

Repository: `Revty79/kindereddominion`

Improve the physical feel, responsiveness and clarity of card placement during gameplay.

Preserve the existing authoritative gameplay engine and established placement rules.

## 1. Existing gameplay review

Inspect:

- Current battlefield rendering.
- Hand rendering.
- Card selection.
- Placement validation.
- Match action submission.
- Active turn state.
- Existing viewport corrections.
- Full-bleed card rendering.
- Touchscreen support.

Reuse the existing card renderer and authoritative gameplay interfaces.

Do not create a parallel game engine.

## 2. Selected card animation

When the active player selects a playable card:

- Visually lift the card from the hand.
- Apply a smooth selection animation.
- Slightly enlarge or elevate the selected card.
- Display a floating representation that follows the pointer.
- Keep a recognizable placeholder in its original hand position.
- Clearly distinguish the selected card from the remaining hand.

The floating card must remain offset from the pointer so it does not obscure the targeted tile.

Preserve card artwork and readable gameplay information.

Selection is not a gameplay action and must not change the authoritative match state.

## 3. Desktop interaction

Support both:

### Click-to-select

- Click a card to select it.
- Move the pointer around the battlefield.
- Click a legal destination to commit placement.

### Traditional dragging

- Press and drag a card from the hand.
- Move it over the battlefield.
- Release over a legal destination to commit placement.

Both interaction methods must use the same authoritative action validation.

Prevent duplicate action submission when pointer and click events overlap.

## 4. Touchscreen interaction

Support equivalent touchscreen behavior.

Allow:

- Tap-to-select.
- Dragging with a finger.
- Selecting a destination.
- Confirming placement when required by the chosen interaction mode.
- Cancelling selection.
- Inspecting cards without accidentally placing them.

Ensure touch interactions do not cause accidental browser scrolling, text selection or unintended page navigation within the battlefield.

Do not disable ordinary touch scrolling elsewhere in the application.

## 5. Cancellation

Allow the player to cancel an uncommitted selection.

Support appropriate cancellation through:

- Escape key.
- Clicking an explicit cancel control.
- Selecting another card.
- Returning the dragged card to the hand.
- Releasing outside a valid placement target.
- Relevant touch cancellation behavior.

Cancelled selections must not consume cards, modify placement tokens, advance the turn or change scores.

Animate the selected card returning to its hand position.

## 6. Legal placement communication

Use authoritative existing placement rules.

While a card is selected:

- Clearly identify legal destination tiles.
- Distinguish unavailable destinations.
- Show the currently targeted tile.
- Prevent illegal placement submissions.
- Provide understandable placement rejection messages.

Do not invent or approximate gameplay legality using presentation-only rules.

The detailed affected-tile and ability preview system will be completed in V1.6D.

Prepare a reusable interface for placement preview information without implementing a duplicate rules engine.

## 7. Placement animation

When a player confirms a legal destination:

- Prevent repeated submissions.
- Submit the authoritative game action.
- Present a pending state if necessary.
- Animate the selected card into the destination.
- Reconcile the presentation with the accepted server result.
- Update the hand and battlefield correctly.
- Preserve authoritative turn progression.

If the action is rejected, return the card to an appropriate selected or unselected state without losing it.

Do not assume that a successful visual animation means the server accepted the action.

## 8. Battlefield placement numbers

Increase the visual size and prominence of placement numbers shown on battlefield tiles.

Requirements:

- Substantially larger than the current presentation.
- Strong readable contrast.
- Appropriate scaling for available tile size.
- Consistent positioning.
- Clear readability on desktop and touchscreens.
- No unnecessary obstruction of occupied cards.
- No gameplay meaning conveyed solely through color.

These changes apply to battlefield placement indicators.

Do not enlarge or redesign the statistics printed on the existing full-bleed cards.

## 9. Input and state integrity

Handle:

- Rapid clicking.
- Repeated drag attempts.
- Changing selected cards.
- Invalid drop targets.
- Pointer cancellation.
- Touch interruption.
- Browser focus loss.
- Match state changes during selection.
- Network delay.
- Rejected actions.
- Opponent turns.
- Match completion.
- Returning to a saved match.

Prevent player actions during states where the existing rules prohibit them.

Ensure selection and floating-card presentation never alter hidden information or game outcomes.

## 10. Performance and accessibility

Keep animations responsive and lightweight.

Prefer transform and opacity animations over unnecessary layout recalculation.

Avoid excessive pointer-triggered rendering.

Support reduced-motion preferences.

Provide keyboard-accessible card selection, target navigation and placement confirmation.

Maintain the accepted gameplay viewport behavior.

Test on ordinary hardware rather than assuming a high-performance gaming computer.

## 11. Automated testing

Test:

- Click selection.
- Drag selection.
- Pointer following.
- Legal placement.
- Illegal placement.
- Selection cancellation.
- Card switching.
- Duplicate submission prevention.
- Touchscreen placement.
- Keyboard placement.
- Server rejection.
- Network interruption.
- Opponent-turn restrictions.
- Saved-match continuation.
- Reduced motion.

Include compiled browser interaction tests and visual evidence.

## 12. Acceptance criteria

The player must be able to pick up a card, move it around the battlefield, select a legal tile and place it through a smooth, understandable interaction.

Both desktop and touchscreen controls must function.

Battlefield placement numbers must be substantially more readable.

Existing gameplay mechanics, full-bleed card artwork and viewport corrections must remain intact.

Deliver implementation summary, test results, screenshots, known limitations and owner acceptance checklist.

Commit and push validated work.

Do not automatically deploy to homeserver.
