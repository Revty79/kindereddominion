Use Node.js 24, PostgreSQL 18 and the existing ignored `server/.env.local`. Preserve its password, session secret and Stripe settings; keep `COMMERCE_MODE=disabled`. Stop the older backend/frontend terminals with Ctrl+C before launching updated processes. Do not reset the database.

Preserve local work before pulling. Verify that the read-only status names **kindred_dominion_dev**, role **kindred_dev**, loopback port **5432**. A November 27 read-only check found schema **7**, with **15 pending migrations**. Isolated migration tests did not migrate that database.

## Build and manage a deck

1. Open **Deck Builder**. Compare the complete collection with saved battle decks; a collection is not a battle deck.
2. Choose **Create deck** for an empty server-stored draft, or choose a **Recommended formation** and create a draft from it. Official recommendations remain available; an explicitly activated starter recipe can supply updated recommendations and alternatives.
3. Name the deck. Keep **Mixed Kindreds** to use owned creatures from different Kindreds, or explicitly select a Kindred restriction. Preserve or select the intended competitive eligibility. Standard/Free Play and Classic/Domination retain their established rules.
4. Search by name, permanent ID or ability. Use Kindred, ownership/availability, collection, rarity, placement, power, mechanic and evolution filters. Collection results render at most 24 identities per page; card illustrations load lazily.
5. Add individual copies. **Owned**, **Selected**, **Remaining** and **Deck limit** distinguish ownership from permission to include copies. The selected-card panel's − removes one copy; + adds one within the current restrictions. Inspection preserves the editor context and provides readable rules.
6. Review the 15-card counter, placement/Kindred distributions, duplicate count, abilities and evolution support. Strategic guidance does not block a legal unconventional deck. Actual rule or ownership failures prevent **Save deck** and match creation.
7. Use **Save draft** to retain an incomplete or currently invalid deck. Registered unowned, retired or no-longer-published identities can remain for repair; saving them grants no ownership. Arbitrary unknown identities are not accepted into permanent deck slots.
8. Use **Save deck** when the exact list is legal. Select it for battle. Rename, duplicate or delete saved decks through their controls. Deletion requires confirmation and retains collection assets and previous match history. An invalid saved deck duplicates as a repairable draft.

The same owned copies can appear in several saved decks. Decks do not consume or permanently reserve cards.

## Understand working-edit recovery

Working edits autosave separately from the last explicitly saved deck. Clear **unsaved**, **saving**, **saved on server**, **offline** and **conflict** states show their status. Leaving the page or reloading can resume the working copy. It cannot enter battle until explicitly saved as a legal playing deck.

During a temporary disconnect, edits are kept in an account-scoped device recovery entry and retried when connected. Each editing session has a distinct recovery key. This is a fallback for unsent changes; the server remains authoritative. If device storage is disabled/full and the connection also fails, keep the page open until a successful server save. The application is not a cold-start offline client.

To test conflicts, open the same deck in two independent browser sessions, save different working changes and inspect the conflict warning. The newer server edit must remain. Choose **Review current server edits**, or **Save my edits as separate draft** to keep both. No automatic merge or silent overwrite occurs.

**Discard working edits** requires confirmation and restores the last saved deck. The server retains a revision tombstone so that discarding and recreating a working copy cannot make an old browser revision valid again. Clearing working edits does not consume cards or modify an existing match.

## Enter battle and repair ownership changes

Open **Play**, select a saved deck, review its composition/count/legality, game mode and published opponent. The selected legal deck is remembered on the server; starting a normal match also records the selection. The existing computer AI is displayed honestly; this milestone introduces no new difficulty levels.

Only legal, ordinary saved decks can start an ordinary match. An invalid deck remains inspectable, with a **Repair this deck** route. The server revalidates ownership, copy limits, format eligibility and the reviewed deck revision at match start. A concurrent edit requires refreshed battle settings.

Purchases, trades, administrative inventory changes and competitive publication can make a saved deck valid or invalid. Use **Refresh owned quantities** or **Refresh collection and decks**; the collection/deck/battle pages also refresh on entry, focus, reconnection and periodically while visible. Deck contents remain unchanged until the player explicitly repairs them.

Once started, a match has its own authoritative card/rule snapshot. Editing a deck or changing ownership does not change that match. Existing unfinished matches remain available under **Continue your campaign**.
