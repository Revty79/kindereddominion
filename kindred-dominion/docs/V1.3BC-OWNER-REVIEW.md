# Owner review and provisional decisions

The supplied 150 creatures, printed power, placement type, influence and intended abilities are retained. Five supplied starters remain exact, with 15 distinct cards each. Names, statistics and rarity remain provisional; collectible identities are permanent. No automatic balancing or final illustration was performed.

## Phoenix and resurrection

M027 requires M003 for evolution, including resurrection by evolution. The supplied starter contains one Firebird; evolving it puts that instance beneath Phoenix. A buried/dead predecessor is not a living battlefield host. Destroying Phoenix therefore cannot resurrect it in that unchanged starter without another eligible living Firebird.

Both branches are verified with actual Cerberus destruction: no living Firebird blocks resurrection; a second living Firebird permits one return through evolution. Lineage limits and inherited modifiers remain enforced. Two OWNER sandbox experiments expose this distinction.

A separately labelled simulation alternative replaces M006 with a second M003. It is not an official starter change. Its 30-match sample per scoring mode recorded no Phoenix destructions or resurrections, so it cannot establish ordinary-game resurrection frequency. See [balance findings](v1.3bc/PRELIMINARY-BALANCE.md). Owner review can retain this restriction, later change the deck, or separately authorize a design change. This release keeps the supplied design and starter.

## Explicit implementation judgments

- Owner adjacency is four orthogonal neighbors. Old laboratory `adjacent` selectors retain eight neighbors. Influence mirrors horizontally for the opposing player.
- Triggered abilities default to one activation per event and match; explicit repeat limits override that default. Vampire/Elder Vampire share a feeding activation identity so evolution preserves used lineage activations.
- Lesser Mimic reads an ally's pre-dynamic power, including permanent changes and continuous contributions, using V1.3A's safe calculation. It does not recursively copy dynamic results. Sacrifice values capture effective power before removal.
- Historical deaths include sacrifices and count each destruction once. Evolution, return and banish are not deaths. Sacrifice gifts address the actual incoming replacement after it arrives.
- Replacement/evolution rank metadata defaults to II; upper evolution stages are III. It describes progression without adding token requirements to those placement types.
- Wolf tags apply to the three Wolf stages; relevant Nature mammals receive Mammal, skeletal Undead receive Skeletal and all Constructs receive Construct. Gargoyle, Enchanted Orb and Living Grimoire also carry Construct across Kindreds, allowing thematic mixed-deck interactions. The [classification registry](v1.3bc/CLASSIFICATIONS.json) exposes assignments.
- C016 and C020 compare positive fortification against the actual configured maximum. This blocking requirement adds `maximumFortification` to the numerical DSL in engine 1.3.1. Zero-cap fields do not count as fortified.
- Artwork associations use permanent lowercase IDs. All 150 illustrations await approval. Draft creature art is never automatically included in invited-player builds.

The [architecture](V1.3BC-ARCHITECTURE.md) and [Master Card Mechanics](MASTER-CARD-MECHANICS.md) define these interpretations. Future balancing, naming and artwork updates should create explicit versions/revisions while retaining identities and historical snapshots.

## Human testing priorities

Mythical led the computer starter samples; Constructs lagged. Review Elder Dragon, Nature Wolf/aura formations, fortification development, Undead first-seat advantage and low-use Rank III cards with humans. These observations are not approved redesigns. Physical phones, owner usability acceptance and human competitive balance remain pending human evaluation.

## Naming review

Kindred Dominion is a working title; all card names remain provisional. A preliminary search identified an existing commercial game titled **Dominion**, sharing a word with this title. That warrants review before commercial naming decisions; it does not establish infringement or clearance. [Rio Grande Games' Dominion page](https://www.riograndegames.com/games/dominion/).

No comprehensive trademark, common-law, international, domain or card-name clearance was performed. Future review should include similar marks and relevant markets. [USPTO federal search guidance](https://www.uspto.gov/trademarks/search/federal-trademark-searching), [USPTO comprehensive clearance guidance](https://www.uspto.gov/trademarks/search/comprehensive-clearance-search-similar-trademarks).

No Final Fantasy illustration, character, logo, sound or other proprietary franchise asset was added. Permanent IDs and artwork relationships are independent of display names and branding.
