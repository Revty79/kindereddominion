## Backup and restoration

DEV was backed up before migration and after populated browser acceptance. A custom-format populated dump was verified by pg_restore --list and SHA256, restored into a new database on a separate owned loopback postmaster, and compared across all 27 tables. Restored content, exact engine replay signatures, private workspace history and inventory ledger reconcile. A real browser logged into the restored account, retrieved its 30-card collection/decks/completed replay/statistics and opened the restored private Studio. The original DEV database was never overwritten. Final paired source/dump restoration evidence is recorded in the release receipt.

## Failures encountered and resolved

- Windows pg_ctl inherited output pipes kept an otherwise successful isolated start waiting: use ignored stdio for that background process only.
- Exact replay validation exposed JSONB object-order changes: migrations preserve game records and workspaces as JSON, retaining existing signatures.
- Repeated synthetic signup exhausted real throttles: isolate test addresses/reset only disposable loopback fixture counters; local DEV has an explicit bounded signup allowance. Authentication checks remain enabled.
- Accessible select labels, an exact Studio field locator, and a creation-response wait were corrected in the browser harness. Random matches could finish earlier than an assumed reload point; the harness keeps a legal opening and reloads after two real placements, without changing rules.
- Copying source PNGs or documentation caused Windows EBUSY in the Vite watcher. Non-runtime masters/docs/build/diagnostic folders are ignored. An interrupted 25/28 browser run is not counted as final acceptance; the suite is repeated from isolated release source.
- Reusing a disposable database exposed an old fixture's assumption that no higher gameplay revision existed. Expansion fixtures now retain latest definitions and allocate unique synthetic numbers. Publication's revision/retirement checks were kept intact.

## Limits and owner validation

Docker/Compose execution is explicitly owner-deferred because this Windows machine lacks Docker/WSL. Ubuntu TEST/PROD were not accessed, migrated, seeded or deployed. Physical mobile-device testing, external security review, load tests, public hosting, account recovery and multiplayer remain outside current acceptance. Browser cross-context proof is not physical-device acceptance. Prior large balance simulations were preserved, not rerun or used to rebalance the owner cards.

Private raw reports, screenshots, account fixtures, configuration, dumps and Git bundles stay ignored under `.local/v1.3d`; concise non-secret results are committed. Incoming owner/Ember PNGs remain untouched and outside this release's staged files. Their final approval/publication remains separate.
