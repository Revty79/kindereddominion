## Changes

Additive migration ten, `1796200000000_inventory_reservations.cjs`, adds trading-account restrictions, immutable reservation scopes, per-lot quantities/purpose/reference/expiry, final release state and conservative unknown-reservation anchors. It does not activate trading, change balances/ownership or invent offers for existing counters. No destructive down migration is available. Published trading configuration defaults paused and uses the existing draft/publication/history/rollback service.

`trading-rules.ts`, `trading-inventory.ts`, `trading-publication.ts` and `trading-inventory-routes.ts` provide bounded card-only quantities, configurable requirements/limits/origins/holding periods, account eligibility, cycle-checked acquisition ancestry, sorted source-lot locking, available-copy calculation, atomic durable reservations, exact-scope idempotency, final release, server expiry and counter reconciliation. Traversal has no arbitrary transfer-count cutoff; the existing database statement timeout bounds query execution. Subsequent bilateral operations must acquire both player locks and the combined source ancestry in deterministic order before reserving or settling.

Starter, first-copy, unknown legacy, administrator and sandbox copies stay bound. Every source in a transfer ancestry must retain its environment, tradeability and restriction/holding checks. Account restrictions and permanent sandbox classification are enforced. Original purchased holds cannot be reset or erased by an incoming transfer. The current milestone exposes only authenticated own-inventory eligibility; it does not expose a generic player reservation endpoint, offers or transfers.

The weekly challenge provenance defect identified in E.0 is corrected: an additional-copy claim derives achievement provenance from its actual reward definition, while first-copy grants remain bound. No historical rows are relabelled. Five configurable DEV proposal challenges, one per founding Kindred, offer one explicitly tradeable additional copy after twenty eligible battles with actual Kindred participation in a UTC week. These require normal verified activity and an explicit once-only claim, supply a free trading path and never change combat statistics. Existing published settings remain immutable; the new proposal is not automatically selected or backfilled. This is a DEV balancing proposal, not a permanent commercial policy. Tournament implementation remains inactive.
