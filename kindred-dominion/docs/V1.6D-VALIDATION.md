# V1.6D tactical preview validation

November 27, 2026. Assignment: [Authoritative Tactical Placement, Battlefield Influence and Ability Previews](V1.6D-ASSIGNMENT.md). Parent revision: `d92587f7e15e9b95a59406ec4405fee09a1ea091`.

## Implementation and preview contract

The persistent player battlefield now requests authoritative tactical previews while a selected card targets a tile by pointer, finger or keyboard. Pattern reach, actual affected tiles, token/fortification changes, ownership, power, destruction, protection, replacement, evolution, resurrection, return/banishment, auras, dynamic power and conditional ability explanations use the existing engine and published card definitions. No card statistics, IDs, evolution prerequisites, artwork, scoring rules or ordinary gameplay outcomes were changed.

The default **Review first** and optional **Place directly** controls from V1.6C remain. Hovering is not a turn. Clicking an invalid destination never submits a gameplay action. Review mode can reuse a current revision-matched hover response; the action endpoint always checks the actual saved match again.

A preview covers the player's action and known automatic effects, stopping before the next player's private choice or an earlier private/random boundary. It excludes the computer's chosen response. **Complete** means those automatic visible effects are known, not that the score after the computer responds is guaranteed. An incomplete preview shows a known prefix and identifies its uncertainty. Tiles retain their current values; projected values are separately marked **PREVIEW**. **PATTERN** marks printed reach without promising a change.

## Systems changed

| System | Implementation |
| --- | --- |
| Shared placement validator | `placementIssue` returns structured reasons from the existing validator branches; `placementError` remains a compatible string wrapper. Ordinary engine/action validation uses the same conditions and messages. |
| Observer control | `ResolutionPause` stops an observed clone without becoming a gameplay fault. Diagnostics mark private generation, random target sampling and the next player's decision. Observer state capture can select relevant steps. Normal actions never construct a pause. |
| Existing preview evaluator | `actionPreview` now stops execution at a boundary instead of completing hidden resolution and then trimming its output. The player tactical path also includes automatic visible turn transitions. Legacy practice keeps its existing immediate boundary and controls; its uncertainty text now distinguishes private generation and random selection. |
| Public tactical projection | `src/ui/tactical-preview.ts` turns actual resolution snapshots into allowlisted tile values, net numerical changes, ordered intermediate changes, public ability definitions/conditions, pattern reach, scores and uncertainty. It never returns the engine state, seed/RNG, private zones, raw diagnostic contexts or activation/history blobs. |
| API | Owner-only `POST /api/matches/:id/placement-options` and extended existing `POST /api/matches/:id/preview`, both strict, authenticated, CSRF-protected and revision-bound. Invalid reasons distinguish turn/hand, unowned/enemy territory, occupied positions, tokens, hosts and prerequisites. |
| Preview resource control | Combined 120 requests/minute per player; existing generic API limit remains. A process-local cache is limited to 32 entries, two MiB total, 128 KiB per retained entry and 15 seconds. Ownership/revision checks precede every cache lookup. |
| Evaluation budget | At most 192 diagnostic observations and 48 captured snapshots, with snapshot count reduced for larger input states. Inputs above one million serialized characters return a conservative pattern/uncertainty response. No wall-clock-dependent truncation is used, so equal inputs and work budgets give repeatable known-prefix results. Long chains remain explicit partial previews rather than guessed successes or faults. |
| Player integration | Debounced 140 ms target requests; no recalculation for pixel movement within one tile; bounded client caches; cancellation and latest-key/generation checks reject late responses even when a transport ignores abort. Changes to selection/revision, cancellation and leaving an unchosen target clear the overlays. A deliberately chosen review destination remains available for confirmation. |
| Presentation | Existing full-bleed cards and larger V1.6C token numbers are retained. Badges distinguish tokens **T**, power **P**, fortification **F**, territory **CAP**, destruction **X**, protection **SH**, replacement **R**, evolution **EV** and other effects using text/symbols as well as color. Conditional abilities have **IF** explanations. Expanded details are optional. |

The floating portrait is placed clear of the target and all highlighted preview tiles, including its caption. It may move beside the affected group or over the hand area. If an exceptionally constrained viewport leaves no safe position, the floating copy is hidden while the recognizable hand placeholder remains; affected tiles stay readable. Pointer movement uses animation-frame transforms rather than rerendering the collection. Reduced motion remains supported.

## Hidden information and uncertainty

- Private draws stop before a card is taken from the draw pile. Hand generation and random target sampling have equivalent boundaries. Later dependent effects are not simulated or presented as guaranteed.
- Private draw/generation-history dependencies, including reachable summoned/evolved/replacement definitions, are conservatively marked uncertain rather than testing a hidden condition. Known public pattern information remains available.
- The response contains only the player's selected instance, public card definitions, board values, sanitized explanations and revision metadata. New hidden instances, the opposing hand, draw order, seeds, RNG state, raw events and full match records are absent.
- Actual game actions retain their original transaction, operation-key, revision and reward-settlement safeguards. Preview routes call neither action persistence nor economy/progression settlement.
- Ordinary player previews can reveal public tactical consequences, such as an existing shield blocking destruction; they cannot probe the outcome of a future random selection or private draw.

## Reproduction and limits

Run the existing root/backend type checks, `npm.cmd run test -- --maxWorkers=1`, `npm run test:database` against a verified registered disposable PostgreSQL 18 target, backend/full/player/control builds, asset validation and backend-isolation validation. Regenerate the declared examples with `node --import tsx scripts/export-tactical-examples.mts`. Compiled acceptance is `server/tests/browser/tactical.spec.ts`, explicitly enabled with `KINDRED_TACTICAL_ACCEPT=yes`, API port 3086 and frontend origin `http://127.0.0.1:5247`; commerce and testing acquisition must be disabled. Services are started/stopped only by the enabled test. Credentials and raw diagnostics are ignored.

Previews intentionally stop at uncertainty, private dependencies or a work budget. A pattern can be highlighted without an actual numerical change. A complete preview excludes the computer's response; an incomplete one can exclude later chained effects as well. Neither is a promise of the final match outcome. The legacy local practice page retains its older controls and immediate-preview scope. Physical-device acceptance and subjective readability/animation review remain owner tasks; Chromium touch/CPU throttling are engineering checks.

Follow [the owner checklist](V1.6D-OWNER-ACCEPTANCE.md). No later milestone, new card mechanic, balance change, V1.6A starter activation or live payment activation was undertaken.
