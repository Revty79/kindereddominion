# V1.3D security implementation and limits

Passwords use asynchronous Node scrypt (N=131072, r8, p1, random 16-byte salt, 64-byte key, 192MiB ceiling), with at most two concurrent hashes. [Node crypto documentation](https://nodejs.org/docs/latest-v24.x/api/crypto.html#cryptoscryptpassword-salt-keylen-options-callback) describes the primitive. Plaintext passwords are never stored in tables or ordinary logs. The database secret is only in ignored private backend configuration.

Sessions use random 256-bit opaque bearer tokens; PostgreSQL stores a secret-keyed HMAC, expiry and independent CSRF token. Cookies are HttpOnly, SameSite=Lax, path `/api`; hosted configuration requires Secure/HTTPS. Login rotates, logout deletes, disabled accounts fail every request and password reset revokes all sessions. No upsert can resurrect revoked tokens. Mutations require exact Origin and bound CSRF, including login/signup. CORS allows only the configured origin; arbitrary forwarded client IPs are not trusted.

Atomic PostgreSQL limits cover API traffic, anonymous sessions, registration and login IP/username. Defaults: 600 API calls/minute, 60 anonymous sessions/hour, 10 registrations/hour, 30 logins/IP/15 minutes and 12 logins/username/15 minutes. Local DEV validation uses a documented allowance of 30 registrations for synthetic signup. Isolated tests reset only disposable keys. Expired rows cannot authorize access; conservative retention/cleanup needs deployment review.

Private APIs derive the actor from the session and check roles server-side. Profile schemas exclude privilege fields. Grants, publication, match completion and progression are not client-trusted. Official publication is an operator/source-controlled command. SQL uses parameters and bounded validated identifiers. Deck/match/Studio records are scoped to the actor; foreign IDs do not disclose existence.

Frontend logout/identity changes clear private caches and discard late responses; sibling tabs receive a secret-free session-change signal. Failed new-account loading cannot display the previous collection. Credentials are absent from frontend bundles, Docker build arguments and API responses. Vite denies private server/config/backup directories; production NGINX blocks source/private paths. Request logs include only ID/method/route template/status. [Fastify logging](https://fastify.dev/docs/latest/Reference/Logging/) explains serializer considerations; default body/header logging is disabled here.

Official artwork requires relative stable refs, manifest/source/runtime checksums, existing image validation and explicit production approval. Data URLs are restricted to validated private Studio drafts, never official definitions. Source masters remain separate from optimized runtime assets. Existing artwork tests cover malformed images, missing/corrupt refs and unsafe SVG; new checks cover private source denial and production packaging.

DEV is loopback only. Integration uses a different owned postmaster, generated credentials, private manifest/token and registered database list. TEST/PROD requires HTTPS, Secure cookies and invite/closed registration; CLI commands require explicit acknowledgement. Reset is never enabled for owner DEV/TEST/PROD. Browsers receive no database credentials.

## Remaining work before public/competitive use

This is a locally validated invited-testing foundation, not an independent security certification. External review, MFA, self-service recovery, email delivery, privacy/retention policy, monitoring, backup encryption/key custody and resource/load testing remain future work. The existing deterministic 32-bit seed model is preserved; competitive RNG needs separate rules/security review.

The owner's local DEV role owns its dedicated schema. Future TEST must use separate migrator/runtime credentials, private PostgreSQL access and a reviewed HTTPS proxy. No live TLS/proxy/firewall changes were made. Container clients currently share the internal proxy IP because trustProxy=false; throttles remain conservative/shared until specific trusted proxy CIDRs are reviewed. Never trust arbitrary forwarded headers.

Backups/private exports contain account hashes and draft/gameplay information. Git bundles include committed files, not untracked Ember masters/browser saves. Store private configuration separately, restore into isolation first and protect backup access. A fresh restoration secret invalidates copied sessions. No client-writable currency, rewards or commercial systems exist.
