## Roles and grants

A DBA must prepare the dedicated database and nonsuperuser migration owner. Keep runtime free of DDL, role/database creation and superuser privileges. After migration/seed grant CONNECT, kd USAGE, table SELECT/INSERT/UPDATE/DELETE and sequence USAGE/SELECT; set matching DEFAULT PRIVILEGES **for the actual migration owner**. Immutable triggers still constrain writes. Do not give runtime membership in migration owner.

Illustrative SQL for later review against actual TEST roles, never executed here:

```sql
GRANT CONNECT ON DATABASE kindred_dominion_test TO kindred_test_runtime;
GRANT USAGE ON SCHEMA kd TO kindred_test_runtime;
```


## Update, rollback and scheduled backups

Stop application writers, record commit/image/content/schema, take a consistent dump plus verified source bundle, then rehearse new source/migrations before restart. Retain old compatible images; never overwrite immutable release tags. Schema-compatible rollback may select an older release/image. Incompatible rollback requires restoring the matching backup into a **new** database and a separately authorized connection cutover. Preserve newer data until the recovery decision.

Host backups require Node 24 and matching PostgreSQL client tools under a restricted operator account. Runtime/maintenance images intentionally lack pg_dump/pg_restore; their backup CLI cannot work without these native tools. Set PG_BIN appropriately. Pair database receipts with Git/official assets and encrypted private environment backups, and keep an off-host copy. Uncommitted Ember originals need separate backup.

After deployment authorization prepare a dedicated systemd oneshot/timer for daily verified backups, owner-approved retention and failure alerts. None is installed here. Schedule isolated restoration plus browser login/read rehearsals, not merely file-existence checks. Confirm free space, encryption keys and off-host recovery before removing older backups. Avoid raw dumps/credentials/private records in ordinary logs.
