# Kindred Dominion — V1.6F
## Last Move Inspection, Visual Replay and Player Presentation Preferences

Repository: `Revty79/kindereddominion`

Implement a complete player-controlled gameplay inspection and presentation preference system.

Extend the accepted V1.6D tactical preview and V1.6E authoritative presentation-event infrastructure.

## 1. Objective

Players must be able to understand what happened during the most recent move, even if they missed its original animation.

Provide inspection and visual replay without changing authoritative match state.

## 2. Last Move control

Add a clearly accessible Last Move control to the gameplay interface.

The control must not obstruct the battlefield, cards or existing essential gameplay controls.

Allow the player to inspect the most recent accepted and publicly visible gameplay action.

Include opponent moves and the player's own moves.

Where useful, allow switching between the most recent player move and most recent opponent move.

## 3. Move details

Display available authoritative information including:

- Acting player.
- Played card.
- Card artwork.
- Placement location.
- Previous visible battlefield values.
- Resulting visible battlefield values.
- Placement influence.
- Ability activations.
- Affected cards.
- Power changes.
- Ownership changes.
- Evolution.
- Destruction.
- Score changes.

Use the actual action result and recorded presentation events.

Do not reconstruct speculative actions from incomplete information.

Clearly identify any historical details that are unavailable.

## 4. Battlefield inspection

Allow the player to visualize the affected battlefield positions associated with the inspected action.

Reuse V1.6D and V1.6E effect highlighting.

Show:

- Original placement target.
- Affected tiles.
- Relevant source and target cards.
- Numerical changes.
- Effect direction where useful.

Clearly distinguish historical inspection from the current live battlefield.

Historical inspection must not make a previous state appear to be the current authoritative state.

## 5. Visual replay

Allow replaying the most recent supported move presentation.

Replay should reproduce the publicly visible action sequence using recorded presentation events.

Support:

- Replay from the beginning.
- Skip to the final result.
- Stop replay.
- Return immediately to current gameplay.
- Step-by-step event inspection where appropriate.

Replay must not:

- Submit another gameplay action.
- Modify match state.
- Change scores.
- Consume cards.
- Advance turns.
- Trigger abilities again.
- Grant currency.
- Grant experience.
- Advance challenges.
- Generate duplicate achievements.
- Expose hidden information.

Use presentation-only state.

## 6. Incoming action handling

Prepare for future real-time multiplayer.

If authoritative match state changes while historical inspection or replay is active:

- Preserve incoming authoritative information.
- Notify the player appropriately.
- Return to the current state when required.
- Prevent stale action submission.
- Avoid losing newer accepted gameplay events.

Historical replay must not pause or extend authoritative turn deadlines.

Do not implement multiplayer networking during this milestone.

## 7. Persistent recent action history

Retain sufficient recent public presentation information to support move inspection after:

- Browser refresh.
- Match resumption.
- Application restart.
- Temporary network interruption.

Use the existing persistent match and event architecture where possible.

Do not duplicate complete match state unnecessarily.

Apply bounded retention appropriate to the latest-move functionality.

Older matches without compatible historical presentation information must remain playable.

Do not fabricate missing historical action details.

## 8. Animation preferences

Implement persistent per-player presentation preferences.

Initial supported modes:

### Normal

Full standard placement and effect animations.

### Fast

Shortened animation durations while preserving understandable effect ordering.

### Reduced motion

Minimize spatial movement and distracting visual effects while retaining readable state changes.

### Instant

Immediately display the accepted authoritative result with minimal transitional presentation.

Players using faster modes must still be able to inspect the most recent move.

Preferences must not change game outcomes, opponent intelligence, match rewards or authoritative timing.

## 9. Additional presentation settings

Provide reusable configuration for applicable preferences such as:

- Card movement animations.
- Ability animations.
- Score animations.
- Battlefield highlighting.
- Effect descriptions.
- Animation speed.
- Future sound effects.

Only expose settings for implemented functionality.

Do not present nonfunctional controls.

Respect system reduced-motion preferences by default where practical, while allowing appropriate explicit player choice.

## 10. Preference persistence

Store player preferences using the existing persistent account settings architecture or a compatible extension.

Requirements:

- Server-side validation.
- Safe defaults.
- Existing account migration.
- Persistence across sessions.
- Compatibility with multiple devices.
- Appropriate fallback when a preference is unavailable.

Do not store gameplay-critical authoritative state in presentation preferences.

## 11. Accessibility

Ensure the inspection and replay experience supports:

- Keyboard navigation.
- Touchscreen use.
- Readable text.
- High-contrast effect indicators.
- Reduced motion.
- Non-color-only effect communication.
- Clear focus management.

The interface must remain usable within the accepted desktop and mobile gameplay layouts.

## 12. Performance

Avoid excessive retention of presentation snapshots.

Use bounded event payloads.

Reuse the existing animation system.

Ensure replay cancellation safely releases temporary presentation resources.

Prevent repeated replay requests from generating unnecessary server-side gameplay processing.

## 13. Automated testing

Test:

- Last move inspection.
- Player move inspection.
- Opponent move inspection.
- Historical battlefield highlighting.
- Replay.
- Replay cancellation.
- Step-by-step inspection.
- Browser refresh.
- Saved-match resumption.
- Older match compatibility.
- Incoming state changes during replay.
- Hidden information protection.
- Animation preference persistence.
- Normal mode.
- Fast mode.
- Reduced-motion mode.
- Instant mode.
- Keyboard and touchscreen interaction.
- No authoritative state mutation.
- No duplicate gameplay or economy rewards.
- Existing gameplay regression.

Use compiled browser journeys and deterministic event fixtures.

## 14. Acceptance criteria

V1.6F is complete when:

1. Players can inspect the most recent move.
2. Actual action consequences are clearly explained.
3. Players can replay supported move animations.
4. Replay can be cancelled immediately.
5. Replay does not modify authoritative gameplay.
6. Recent move information survives supported match restoration.
7. Animation preferences persist.
8. All presentation modes remain playable.
9. Hidden opponent information stays protected.
10. Existing game rules and economy integrity remain unchanged.
11. Automated tests pass.

Deliver implementation summary, interface evidence, test results, known limitations and manual acceptance checklist.

Commit and push validated work.

Do not automatically deploy to homeserver.
