# V1.5A read-only validation correction

Date: November 26, 2026, owner local time. This correction is limited to operator validation, regression coverage and upgrade instructions. It introduces no application, database, card, artwork, economy, network-override or credential changes.

## Reported failure and cause

The owner reports that homeserver preflight/status were healthy and all three candidate images built, but the first Ubuntu Docker rehearsal stopped at `building-before-downtime` with `EROFS` writing `/app/node_modules/.vite-temp/vite.config.ts.timestamp-….mjs`. The operator correctly recorded `failed-before-migration`; no live migration was attempted. These are owner-reported Linux results, not a remote test performed by this correction.

The lockfile installs Vite **7.3.8** and Vitest **4.1.12**. Inspection of Vite's installed `loadConfigFromBundledFile` confirms that its default ESM config loader writes the bundled TypeScript configuration into `node_modules/.vite-temp` before test discovery. The previous operator allowed writes to `.vite`, which is a separate transform/test cache. It omitted `.vite-temp`.

## Exact correction and retained controls

The unit-validation Docker argv now includes one additional mount:

```text
--tmpfs /app/node_modules/.vite-temp:rw,nosuid,nodev,size=64m,mode=0700,uid=1000,gid=1000
```

The existing `/tmp`, `/app/.local` and `/app/node_modules/.vite` mounts remain. The root stays `--read-only`; the container remains on `--network none`, drops `ALL` capabilities, retains `no-new-privileges:true`, and inherits the validated maintenance image's `1000:1000` user. No host volumes, secret environment files, database credentials or network access are added. Source and the rest of `node_modules` remain read-only. No config-loader switch, test filter, skipped validation, timeout relaxation or `passWithNoTests` option is introduced.

`unit_validation_command` in `deployment/operator/host.py` centralizes the actual argv so regression checks exercise the command used by `Host.build`. The unchanged invocation remains:

```text
node node_modules/vitest/vitest.mjs run --maxWorkers=1 --no-file-parallelism
```

## Regression evidence

- **23 Python operator tests passed.** Three added regressions cover separate config/transform cache mounts with bounded nonroot permissions; the unchanged full-suite/security/credential boundary; and actual `Host.build` command wiring plus propagation of validation failure before marking a candidate validated.
- A fresh isolated checkout installed the committed lockfile dependencies. The native regression reproduced the missing `.vite-temp` write denial through Node's filesystem permission model, then ran **all 403 existing tests successfully** with the corrected directory allowlist. An attempted ordinary source write was still denied.
- Native versions: Node **24.18.0**, Vite **7.3.8**, Vitest **4.1.12**. Docker's pinned Node image version is unchanged. No test limits were weakened. The model's denial is `ERR_ACCESS_DENIED`, not the owner's kernel `EROFS`; this distinction is intentional and recorded.
- This computer has no usable Docker environment. Linux tmpfs mount execution and the complete updater rehearsal remain for the owner and Ember. The native permission model permits workers/native modules/subprocesses needed by the suite and does not claim Docker's kernel, network or process isolation proof.

Aggregate evidence: [correction receipt](v1.5a-validation-correction.json). Raw regression logs remain ignored under the isolated fixture's `.local/readonly-validation/`; no private settings or account records are committed. There was no connection to homeserver and no application/database restart or migration here.
