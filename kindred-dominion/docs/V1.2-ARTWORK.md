# Portable artwork publishing, packaging and recovery

## Repository contract

```text
public/assets/
  cards/nature/
  cards/mythical/
  cards/arcane/
  cards/undead/
  cards/constructs/
  card-backs/
  battlefields/
  icons/
  animations/
  audio/
  branding/
  manifest.json
artwork-source/
  cards/                 Original imported masters, including immutable revisions
  branding/              Original branding masters
  validation/            Temporary geometric test illustration source
src/content/published/   Versioned definitions referencing repository assets
```

New official assets belong in these standard locations. Audio/animation destinations are established; image publishing is the implemented V1.2 workflow. No audio editor or animation editor is implied.

Card IDs and artwork IDs are independent. Updating an illustration does not rename its card, change stats or break evolution/deck references. Each asset has a stable lowercase ID, a SHA-256-derived revision, portable path, full checksum, media type, size/dimensions, approval level and source-master record. Published metadata references `{id, revision}`. Paths such as `assets/cards/nature/art-sprout-ce9b71e2b4447e2c.webp` are relative runtime references, without drive letters or machine-specific locations.

Old asset/source revisions remain in the registry and repository for historical content/replays. An existing asset revision cannot be overwritten. `.gitattributes` disables text conversion for assets/sources, so SVG and binary checksums remain stable on Windows/Linux and in mobile build output.

## Import experimental artwork into Studio

Open an existing card in Card Editor and select **Local artwork**. PNG, JPEG, WebP and safe SVG are supported. Sources are bounded to 10 MB/40 million pixels; thumbnails are proportionally bounded to 1024×1536 and optimized to WebP. The original source remains separately in IndexedDB metadata and complete Studio backups. No text, borders, statistics or influence diagrams are baked into the image.

SVG uses a strict geometric allowlist and rejects scripts, event handlers, foreign objects, external URLs, embedded images, style blocks/attributes, entities and document types. Safe geometric paths, shapes and local gradients are supported. Unsupported SVG should be flattened/exported to a supported raster or simplified; it is never silently executed. File signatures and actual decoded pixels are checked, not just extensions/MIME labels.

An uploaded image defaults to **Experimental · local only**. Explicitly select testing or production artwork approval. New uploads reset approval to experimental. Artwork identifiers are stable/lowercase and remain editable independently of the permanent card ID. The live preview and library show the image. A testing version activated for normal play freezes the optimized preview for its match, including hands and battlefield creatures.

## Export a reviewed publication

In **Content Versions and Backups**, use **Artwork & content publishing export**:

1. Select a working draft or saved version.
2. Set a new lowercase publication ID and a display name.
3. Select **Temporary / provisional testing package** for V1.2 test assets. Production approval is available as infrastructure for future explicit owner decisions; V1.2 supplied art is testing-only.
4. Check the definition-revision approval checkbox after review.
5. Export the package. Unapproved artwork, malformed definitions or unresolved references block export.

The `.kindred.zip` contains:

- `content.json`: structured definitions and metadata, with portable artwork references and **no embedded source/preview bitmaps**.
- `assets.json`: asset IDs, immutable revisions, source/runtime paths, media, dimensions, checksums and approval.
- `publication.json`: versioned publication schema and a checksum/size record for every included file.
- `public/assets/...`: optimized WebP illustrations.
- `artwork-source/...`: original source masters.

Byte-identical images within a package share a single asset reference. Separate cards can share an illustration without changing card relationships. Conflicting IDs, duplicate byte assets under different IDs, unsafe paths or missing associations are rejected.

## Validate and import into the repository

From `D:\kindereddominion\kindred-dominion`:

```powershell
node scripts/import-content.mjs "C:\path\publication.kindred.zip" --validate-only
node scripts/import-content.mjs "C:\path\publication.kindred.zip"
npm run validate:assets
npm run build
```

The importer first checks the entire package: schema/engine, definitions, dependencies, file manifest, source/runtime checksums, image signatures, full pixel decoding, safe SVG, dimensions, case-consistent relative paths, duplicate assets and approvals. It refuses traversal, external paths, unexpected archive members and archive expansion beyond bounds. No definition/asset is written until validation and conflict checks finish.

Ordinary write failures roll back prior file bytes. Each file replacement uses a temporary file and rename. An abrupt OS/process interruption between files can require rerunning the same validated package; `validate:assets` fails closed on inconsistent references before compilation. Do not deploy/build past a validation failure. Reimporting an unchanged package is idempotent, including harmless JSON formatting differences.

Use a **new publication ID** for a new immutable content version. `--replace` is an explicit reviewed override for an existing definition version; it does not permit overwriting immutable runtime/source revisions. Prefer new IDs for historical preservation. Existing unapproved local files are never automatically imported or published.

Commit the corresponding files together:

```powershell
git add public/assets artwork-source src/content/published
node scripts/validate-assets.mjs --tracked
git commit -m "Add approved testing artwork and content version"
git push
```

Git tracking checks cover runtime files, source masters and published definitions. A normal pull retrieves these same files; there is no artwork migration, browser-data import or external host dependency. A pull that changes dependencies still needs the usual `npm ci`.

## Re-export official content from a clean repository

Source masters are intentionally not shipped into the browser. To package an already committed official version, including its sources:

```powershell
node scripts/export-content.mjs founding-artwork-test-v1 .local\founding-artwork-test-v1.kindred.zip
node scripts/import-content.mjs .local\founding-artwork-test-v1.kindred.zip --validate-only
```

This validates the repository before exporting. During local `npm run dev`, Studio can read only validated image paths under `artwork-source/` through a read-only development middleware, so a package can combine existing official artwork with new local experiments. That middleware is excluded from production builds. Browser re-export in a production build points to the repository command when source masters are absent. To modify an image, import the desired source, keep its artwork ID and approve the new revision; publish under a new content version.

## Production and future mobile packages

Vite copies `public/assets/` into `dist/assets/`. Definitions are bundled from `src/content/published/`. The build uses relative URLs. Images use native lazy loading/decoding and a small packaged fallback instead of eagerly decoding the entire library. Source masters stay outside `dist/`. A future Capacitor package can copy this same static output; V1.2 does not add mobile platform projects.

The packaged testing version appears automatically in Content Versions on a fresh browser with empty storage. **Activate for new matches** to play it. **Restore as new draft** to inspect/edit its imagery in the Studio library. This explicit selection preserves the original V1.1 default.

## Backup and restore

Experimental sources/previews are included in **Export complete Studio backup**. Keep that JSON outside browser storage. Its validated atomic import restores local artwork and card relationships in an isolated browser or another computer.

Official assets are backed up by Git together with their definitions, manifest and source masters; `.kindred.zip` provides an independent portable package. Restore with Git checkout/pull, or validate/import the package into a clean repository. Historical versions retain exact artwork revisions, not a mutable latest-image pointer.

Package bounds: 60 MB compressed, 150 MB expanded, 30 MB per member, at most 2,000 archive members; Studio JSON import is 50 MB. These are explicit safety bounds for this local foundation. Large future artwork batches can require reviewed bound/streaming improvements; they are not silently truncated.

## Temporary acceptance illustration

`artwork-source/validation/sprout-study.svg` is an original geometric study with no card text or statistics. `node scripts/create-test-artwork.mjs` renders the test PNG. The browser workflow imports it, explicitly approves testing artwork, verifies previews/library/hand/battlefield, exports a ZIP and runs repository validation. Its resulting `founding-artwork-test-v1` content and all referenced files are committed. The normal 150-card content remains separately available without this artwork.

Node tests reject unsafe SVG, corrupt pixels, bad checksums/references, duplicate assets, incompatible media and path traversal. Browser tests also cover source/preview persistence and backup recovery. The clean-checkout production test uses a new browser context, activates committed content without importing local files, verifies imagery and injects an image failure to verify the packaged fallback. See [validation receipts](V1.2-VALIDATION.md).
