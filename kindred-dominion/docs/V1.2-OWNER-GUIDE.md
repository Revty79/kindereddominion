# V1.2 owner guide

Start with `Start Kindred Dominion.cmd` or `npm run dev` in `D:\kindereddominion\kindred-dominion`. Open http://127.0.0.1:5173/. Stop with Ctrl+C in the terminal, then Y if prompted. The Developer Studio button is below Begin match on the home screen.

## Choose the content you want to play

Open **Content Versions and Backups**. The original V1.1 version contains the unchanged 30 cards and four test decks. **Founding Kindreds · 150 provisional cards** contains five complete collections and ten new decks. **Founding Kindreds · temporary artwork validation** contains the same 150 definitions and one temporary Briar Sprout image, packaged in the repository.

Click **Activate for new matches**, then **Return to game**. Activation changes new matches only. Select a Kindred's pure starting deck or a mixed test deck in ordinary setup. To inspect or edit a saved version, use **Restore as new draft**. The current working draft is automatically checkpointed before restoration. Restoring does not activate the version.

If you used an earlier Studio build, its working draft is retained. Choose a bundled version explicitly instead of expecting your existing draft to be overwritten.

## Create or modify a card without code

1. Open **Card Library**, then **Create card**, or use Edit/Duplicate on an existing definition.
2. Choose a stable identifier, display name, collection, classifications, base power, rank, placement type, copy limit and development status. Display names can change; permanent card identifiers cannot. Duplicate when you need a new identity.
3. For replacement/evolution, choose named predecessors, classifications and/or a minimum current power. Named options are alternatives; different requirement categories must all match. Branching, multistage and cross-Kindred paths are supported.
4. In **Territorial influence**, click a relative cell and set expansion/token contribution, fortification or overthrow strength. Zero removes that mechanic. Increase the radius for longer patterns. Switch orientation preview between players; only the horizontal direction mirrors. The numbered influence list controls declaration order.
5. In **Ability builder**, add a trigger and one or more effects. Choose self, triggering creature, all eligible targets or a clickable relative pattern. Set friendly/enemy relationships, optional classifications and source exclusion. Add only supported conditions.
6. Set per-event, per-turn and per-match counts where wanted. Blank per-turn/match adds no extra limit; per-event defaults to one. Explicitly choose whether resurrection placement events may activate the ability. Resurrection effects also need a limit. Universal generation and resolution limits remain enforced.
7. Add further effects or abilities and move them Earlier/Later. One multi-target effect is simultaneous; separate effects are sequential. Read the generated executable description and live preview, including ability patterns and prerequisites. Supplementary description/flavor text does not define mechanics.
8. Correct blocking errors and click **Save card**. Reload to verify persistence. Saving a draft does not change saved versions, active games or the ordinary baseline library.

The library filters names/identifiers, collection, classification, placement, rank, power, trigger, effect, territorial mechanic, status and evolution relationships. Sort, inspect complete definitions and open the relationship diagram. Archiving retains references rather than deleting a definition.

## Manage collections and named decks

**Collection Manager** creates stable collection identifiers, display names, descriptions, colors, glyphs and target counts. Renaming a display name leaves references intact. Assign cards and inspect ranks, placement types, abilities and evolution diagrams. Authored/provisional counts are separate from approved-card progress toward 30.

**Create recommended test deck** starts a single-collection draft. In **Deck Builder and Tester**, name decks, assign a strategy, add/remove cards, duplicate a deck and compare composition. Choose a ruleset, pure/mixed restriction and Standard/Free Play. Invalid size/copy/collection restrictions are errors; sparse openings and missing predecessors are advisory. Draft decks can remain incomplete, but simulations/gameplay require legality.

Each supplied pure starter has 15 different cards and can be built from one copy of each card in that Kindred's collection. Free Play still enforces universal safeguards.

## Construct and execute a repeatable sandbox scenario

1. Open **Battlefield Sandbox**. Select a ruleset/content version. **New scenario from ruleset** creates a construction state. Custom dimensions/layouts are authored in Tactical Ruleset Editor.
2. Click a cell to set ownership, tokens and fortification. Choose a definition, owner and destination, then **Add card instance**. Construction can bypass placement requirements but must satisfy structural invariants.
3. Add hand, draw, graveyard and exile cards similarly. Draw order is top-to-bottom; Earlier moves a card toward the next draw. Select an instance to change power, granted protection, resurrection counts and activation restrictions. Prepend previous evolution forms; the final stack must be compatible.
4. Set active player, turn, passes and each player's turns already begun. Execution begins at the configured turn's action step; future beginning/end effects resolve normally.
5. Name and **Save scenario**. Fix validation errors before execution. Duplicate identities, bad zones, nonpositive live power, invalid stacks/counters or neutral occupied positions are blocked.
6. **Execute scenario** locks construction. Choose an active hand instance, click a legal cell, then **Execute placement**. Pass/advance, run one computer turn or both players. The automatic experiment stops at a visible 200-action ceiling without inventing a result.
7. In **Ability resolution inspector**, select a real recorded snapshot. Inspect requirements, targets, conditions, limits, territory, power, protection, lifecycle and score changes. Return to **Show committed state** before another action. Intermediate views cannot interrupt a resolution.
8. **Reset execution** repeats the original construction, including RNG/counters. Undo returns to an earlier committed state. **Edit construction** changes the copy; save explicitly. **Restore saved construction** recovers the saved version. Duplicate before trying different definitions.
9. **Save sandbox replay** retains actions and immutable definitions. Scenario export/import is under Content Versions and Backups.

## Edit experimental tactical rules

Duplicate Classic/Domination in **Tactical Ruleset Editor**. Name the experiment; set scoring, dimensions, token/fortification caps, deck/opening sizes, duplicates and collection restrictions. Paint explicit starting cells. Changing dimensions resets starts to edge columns.

Only Classic/Domination scoring and two-pass/surrender completion are available. Deck size must allow a full replacement hand during mulligan. Invalid dimensions, overlaps or unsafe limits are rejected. Saving a built-in rule creates an experiment and preserves 3×5, 15-card, five-card defaults. Select experiments explicitly in Sandbox or Simulator.

## Run and preserve a simulation

1. Choose working/saved definitions, a tactical ruleset and at least two valid decks in **Match Simulator**.
2. Choose first-two-deck or round robin (including self matches), a seed, mirrored seats and 10/100/1,000/10,000 matches **per pairing**. Round robin totals exceed the preset.
3. Set an action ceiling. It is a simulation limit, not a normal completion rule. Use Free Play for unrestricted duplicate tests.
4. Run. The worker updates progress/elapsed time while controls remain responsive. Navigation is locked until completion/cancellation. **Cancel simulation and preserve results** retains completed outcomes and partial progress; progress also saves periodically.
5. Inspect completed games, draws, timeouts, faults, invariant/loop events, first-player results, length, scores, decks/matchups and card usage. Inclusion is separate from actual play; win association is not proof of strength.
6. Repeat the same content/decks/config/seed to compare deterministic digests/statistics. IDs and elapsed times differ. No automatic rebalance occurs.
7. Export JSON and deck CSV. Up to three representative replays and bounded verbose failures are retained; thousands of full histories are not accumulated. Every failure keeps its seed and request conditions.

The [balance report](balance/V1.2-PRELIMINARY-BALANCE.md) covers 4,720 tests. Nature and Arcane starter results warrant human review; this computer is not an expert-play model.

## Replay and diagnose a normal match

Complete a game in the ordinary interface. Return to setup, open Studio, then **Match Replay and Diagnostics**. Choose its record, navigate Beginning/Previous/Next/Final, jump by action or turn, and inspect both hands, draw order, graveyard/exile and battlefield. Click a creature or select an instance for its definition, stack, modifiers, protections and counters.

Diagnostics rebuild using immutable definitions and verified signatures. A changed draft cannot alter history. Incompatible engines/schemas or divergent signatures are reported. Legacy V1.1 saves can continue; records started from a recovered legacy state begin at that recovery snapshot because earlier actions cannot be invented.

## Checkpoints, backups, restore and artwork

**Create named checkpoint** freezes a valid draft. Testing approval is separate from commercial approval. Compare, restore as a new draft or archive versions. The baseline cannot be archived. Activation is explicit and validates content/decks.

Download **Export complete Studio backup** to preserve all workspace entities and local experimental artwork outside browser storage. Separate exports are available. Import, review names/conflicts, explicitly authorize replacement where needed, then apply the validated candidate atomically. Rejection leaves current content intact. **Restore previous local transaction** downloads a current backup before recovering the prior save.

Use one editing tab. Stale tabs are rejected instead of overwriting newer work; reload to continue. See [artwork publishing](V1.2-ARTWORK.md) for source import, approval, portable packages, repository commands and clean-checkout behavior.
