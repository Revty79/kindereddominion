## Reproduce validation

Normal owner launch and manual test steps are in [the owner guide](V1.4-OWNER-GUIDE.md). The commands below use the explicitly prepared private **isolated** configurations on this computer; the test guards refuse owner DEV:

```powershell
node node_modules/vitest/vitest.mjs run --maxWorkers=1 --no-file-parallelism
$env:KINDRED_ENV_FILE='.local/v1.4/release.env'
node node_modules/vitest/vitest.mjs run --config server/vitest.config.ts

# Free owned acceptance ports 3104/5192 are required; the test starts/stops only its own processes.
$env:KINDRED_RELEASE_APP='D:/kindereddominion/kindred-dominion/.local/v1.4/clean-checkout/kindred-dominion'
$env:KINDRED_RELEASE_ACCEPT='yes'
node node_modules/@playwright/test/cli.js test --config server/playwright.config.ts release.spec.ts
Remove-Item Env:KINDRED_RELEASE_ACCEPT

# Full compiled acceptance requires its matching API/frontend on 3105/5193.
$env:KINDRED_ENV_FILE='.local/v1.4/full-release.env'
$env:KINDRED_ACCOUNT_URL='http://127.0.0.1:5193'
node node_modules/@playwright/test/cli.js test --config server/playwright.config.ts accounts.spec.ts collections.spec.ts identity.spec.ts matches.spec.ts

# Historical local UI regressions use the retained frontend and separately compiled previews.
$env:KINDRED_PLAYER_URL='http://127.0.0.1:5194'
$env:KINDRED_CLEAN_URL='http://127.0.0.1:5193'

Remove-Item Env:KINDRED_ACCOUNT_URL
Remove-Item Env:KINDRED_RELEASE_APP
Remove-Item Env:KINDRED_PLAYER_URL
Remove-Item Env:KINDRED_CLEAN_URL
```

On another machine, first provision the owned disposable cluster with `scripts/pg-isolate.mjs`, create fresh registered test databases, apply/seed through the existing CLI and configure only private test files. Do not copy secrets or private test checkpoints into Git. Production-mode previews still require the API and PostgreSQL; a static preview alone does not implement accounts.
