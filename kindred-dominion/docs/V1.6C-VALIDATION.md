# V1.6C interaction validation

November 27, 2026. Assignment: [Interactive Card Selection, Dragging and Battlefield Placement](V1.6C-ASSIGNMENT.md). Parent revision: `9057fa65701cf6a90561211ca788d9574c2d8b8f`.

## Delivered behavior

The persistent player match screen now supports click/tap pickup, traditional mouse/finger dragging, a lifted hand placeholder, an offset floating portrait, legal/unavailable/targeted destinations, keyboard tile navigation and cancellation. The existing full-bleed `CollectibleCard` renders the hand, floating portrait and battlefield. Printed card statistics, artwork, permanent IDs, card mechanics and engine files are unchanged.

**Review first** remains the default. Choosing a destination by click, tap or drag opens the existing server preview and requires **Confirm placement**. **Place directly**, in the hand header, submits a legal click or drag release immediately. Both modes submit the same existing authoritative action endpoint. Inspection has a separate control and never submits a placement.

Escape, Clear selection, Cancel placement, clicking the selected card again, an invalid/outside/returned-hand drop, pointer cancellation, lost capture, focus loss and hidden-page interruption clear uncommitted input. Selecting another card restores the previous hand placeholder. Cancelled portraits return to their hand position; accepted portraits animate to the destination only after a successful server response. Reduced motion removes these transitions.

Tile token numbers are 24–30px on empty tiles, with occupied values 20–24px (26/22px on short desktop layouts). Previous tile resource typography was 7–10px. Numbers remain in the tile header with strong contrast and explicit token/fortification accessibility labels. Legal placement also uses a plus sign, dashed border and text, while unavailable destinations use a diamond, dotted border and an accessible explanation. Card face typography is untouched.

## Architecture and integrity

| File | Responsibility |
| --- | --- |
| `src/player/useCardPlacement.ts` | Pointer capture, drag threshold, selection, cancellation, keyboard target navigation, presentation animation and requestAnimationFrame floating transforms. Target changes update React state; pixel movement changes the floating element's transform without rerendering the card collection. |
| `src/player/placement-input.ts` | Exact server-legal tuple adapter, revision-bound preview request shape, tile navigation and off-target floating position calculation. This is a reusable input for V1.6D; it does not calculate ability consequences or approximate rules. |
| `src/account/PersistentGame.tsx` | Integrates the controller with the existing server preview/actions and renderers, both confirmation modes, synchronous submission lock, interrupted-response recovery and current saved match refresh. |
| `src/player/placement.css` | Scoped interaction presentation and larger tile numbers; transform/opacity animations and reduced-motion handling. |
| Tests | `tests/placement-input.test.ts`, `server/tests/placement-input.integration.ts`, `server/tests/browser/placement.spec.ts`. The existing viewport cancellation assertion now verifies that Cancel placement returns the selected card, rather than requiring a second Clear selection click. |

Legal destinations come exclusively from `publicMatch.legalActions`, generated by the existing engine on the server. An input is accepted only for the exact match revision, player turn, card instance and legal destination. No tile ownership, rank, tokens or artwork are used to infer legality in the controller. Existing server validation remains the final authority.

A synchronous submission lock closes the pointer/click and rapid-confirmation overlap before React state updates. Pending requests leave the hand and board intact. A successful response updates the saved match; a failed visual transition cannot accept a move. A rejected action retains the card and reports the server error. If an action response is lost, the client reads the saved match before offering a retry. An uncertain identical retry reuses its operation key, and the original server transaction/revision checks prevent duplicate effects.

Focus, reconnection, visibility changes and a twelve-second visible-page interval refresh saved authority without submitting actions. Changed revisions clear stale selection/preview/recorded frames. Background read failures keep the saved position visible. Requests are aborted or ignored after unmount; hidden opponent hands, seeds, private records and full game state are not introduced into the player interface.

## Database incident and preservation

**A target-selection error occurred during this work.** One local CLI migration command omitted `KINDRED_ENV_FILE` and used `server/.env.local`, applying the previously pending V1.5C–V1.6B migrations to normal local DEV: **schema 7 to 22**. This was disclosed while work was in progress. No immediate pre-command backup was captured. No hosted TEST/production database was accessed, and no normal DEV content seed, artwork activation, account changes or fixture writes followed this command.

Subsequent normal DEV operations were read-only auditing and backup. The current schema-22 DEV backup was restored into a newly registered disposable database and verified by the existing restoration checks, including content checksums, saved replays, Studio workspaces and inventory/economy/reservation/trade/commerce reconciliation. Its private receipt and archive remain under `.local/v1.6c/dev-post-migration-backup/`.

The latest existing pre-command DEV backup was schema 6, created November 26 at 9:00 p.m. Denver time (November 27, 04:00 UTC). It was restored separately for an original-column row-hash comparison against read-only current DEV. **24 of 26 compared application relations matched exactly**, including all **13 players, nine decks, 135 deck slots, four matches, 150 inventory rows, 150 inventory ledger rows, six content versions and five Studio workspaces**. All nine historical session rows remained, with four later sessions added. Two historical rate-limit rows differed. In total, **1,982 historical rows** were preserved in the relations with no missing historical hashes. Migration metadata and the disposable environment guard were excluded from this historical comparison.

This historical comparison is not an immediate before/after proof and cannot attribute session/rate changes to a particular operation. No destructive reversal or overwrite of normal DEV was attempted. The error and remaining evidence limit are retained here instead of claiming that all validation was isolated. Remaining automated commands use a private wrapper that explicitly verifies the registered disposable target before launching tests or migration commands.

V1.6C adds **no migration**. Repository schema remains **22**. Its normal automated database/browser fixtures use separate registered disposable PostgreSQL databases. The original gameplay engine, updater implementation, trusted CI workflow, published card content and artwork are unchanged.
