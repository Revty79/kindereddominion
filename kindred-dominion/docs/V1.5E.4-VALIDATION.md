# V1.5E.4 — Notifications, histories and player interfaces

Implemented in isolated DEV on 2026-11-27. Final hosted acceptance remains with the owner. This is a submilestone of E; E.5 safety/administration and E.6 final integration remain required before F and G.

Trading Hall is available through normal player navigation: paginated offers/history, exact-version details, portrait card inspection, own quantity projections and deck warnings, private draft creation/editing/submission, counteroffers, explicit acceptance/decline/cancellation, nonbinding listings, private-by-default additional-copy wishes, public interests, advisory matching and own tradeability/reservations. Search and Kindred/rarity/collection filters use the published catalog. Cosmetic equipment is excluded from the exchanged card previews. A pending explicit confirmation survives browser reload with its original idempotency key; the server rechecks the exact version, eligibility and available inventory.

Migration `1796500000000_player_notifications.cjs` adds persistent owner-scoped notifications with immutable trade-event sources and monotone read timestamps. Asset settlement commits first. Independent projections notify both eligible participants afterward; projection failures cannot reverse or fail the committed exchange. Inbox reads repair missing projections from the retained event outbox. Private draft versions and cancellations never notify the other participant. Received, countered, accepted, declined, cancelled, expired, invalidated and settled events retain private links and causal version/event ordering. There are no external messaging providers.
