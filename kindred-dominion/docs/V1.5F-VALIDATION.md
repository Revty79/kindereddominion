## Final integration corrections

Confirmed provider defect: a charge refund aggregate does not establish each refund's successful current state; a submitted/succeeded refund can subsequently fail. Schema 20 adds current per-refund state, current successful/pending totals and a verification timestamp while retaining the monotonic historical maximum and immutable observations. Complete current history is verified; missing identities/truncated history fail closed. Pending requests and external refunds share the same refundable cap without double counting. Late failure cannot silently erase a reversal or replay fulfillment.

Explicit administrator restoration references an exact earlier reversal, pins current financial state, rejects pending/open/lost financial risk, caps currency to that reversal's remaining recoverable quantity and appends positive ledger entries plus immutable restoration/source receipts. Fixed assets are restored atomically from the retained negative acquisitions; cosmetics remain unequipped. Concurrent replay, changed terms, excessive amounts, foreign sources and repeat fixed restoration cannot duplicate assets. Replacement refunds can reverse the known restored sources in a later reviewed cycle. Historical observations, original purchases, pack results, lifetime first-copy acquisition and unrelated player assets remain retained. Pending recovery is distinguished from corrupt accounting in reconciliation.

Saved commercial pack reveals now link to the original order and describe historical delivery rather than claiming the cards are currently owned. Revealing never regrants a reversed pack. Player and administrator views distinguish current successful refunds from pending amounts and historical maximums. Control provides saved, explicitly confirmed restoration actions and history. The runtime image includes a compiled commerce setup command without requiring development dependencies. The local frontend launcher now excludes inherited Stripe settings and malicious browser-prefixed private variables, alongside database/session credentials.

Files changed span the commerce provider/event/financial/fulfillment/hold/reconciliation/routes modules, the new refund-state/restoration/recovery-integrity modules, schema version and additive migration 20, Shop/Commerce/Control presentation, build/local launcher tools, PostgreSQL/SDK/browser/security regressions and these operational reports.
