# Hosted administration and Developer Studio

V1.5B uses the existing PostgreSQL account, session and role. After installing the reviewed backend and frontend images, log in as **Revty79** at the existing HTTPS game address. An administrator sees **Administration** beside the normal player navigation. It opens **`/api/control/` on that same origin**. There is no second registration or separate password. A developer sees **Development tools**, with Studio and published inspection only.

The 30-card Mythical starter, permanent identity, collection, saved decks and statistics remain in their existing tables. This release does not seed a new owner account or promote anyone automatically. The trusted operator CLI remains the only role-promotion path.

## Available tools

| Section | Actual behavior |
|---|---|
| Dashboard | Current player/account/match/invitation counts and active publication |
| Players | Bounded username/display-name/email search, real ownership, saved decks, match statistics, acquisition and existing pack receipts |
| Account status | Reasoned, audited disable/reactivate for ordinary/developer accounts; disabling revokes their sessions and recovery tokens. Administrator status stays operator-only |
| Card grants | Select a currently published edition, positive quantity and reason. The server transaction, inventory ledger and audit persist together. Reviewing the same request cannot grant twice |
| Invitations | Generate a bounded, expiring tester code, retain it privately, inspect usage and revoke with a reason. The plaintext is returned once; old codes cannot be recovered from listing |
| Grant/audit history | Paginated transactions with actor, target, reason and immutable receipts |
| Published content | Actual active executable definitions, artwork and stored version metadata |
| Developer Studio | Existing private library/editor, artwork import/optimization, supported abilities/placement/influence/relationships, full-bleed previews, sandbox, simulator, versions/backups and publication-package preparation |

Hosted pack templates and economy rules remain unapproved. The application shows existing entitlements and acquisition history; it does not expose a fake pack-grant operation or invent currency, rewards, prices, pack sizes or odds. Local testing acquisition remains prohibited in hosted TEST/PROD.

Initialize Studio from bundled content, then **Open saved private Studio**. New drafts and original/optimized experimental uploads are stored in that account's existing PostgreSQL workspace, with historical snapshots. Sandbox actions, replays and simulations grant no permanent ownership or verified progression. Use a complete private backup for offline recovery. New sandbox/simulation replay artwork uses portable repository paths so records survive moving between the public root and protected Studio subpath. The executable replay/engine validators remain unchanged.

Official publication still requires review, export, the existing repository importer and asset validation, then a committed release. Studio never silently activates drafts in the ordinary catalog. See [artwork publication, backup and restoration](V1.2-ARTWORK.md). Large private workspaces remain subject to the existing 16 MiB request limit; retain exported backups and avoid accumulating unnecessary embedded experimental images/reports. Original official source masters remain in Git, outside web packages.

## Build and authorization boundary

```powershell
npm ci
npm run build:player
npm run build:control
npm run backend:build
```

`dist-player/` continues to omit Studio, simulation workers and unpublished artwork. `dist-control/` is a separate compiled application copied into the backend image. Every HTML, script, worker, image and manifest request under `/api/control/` requires a fresh server-side active developer/administrator authorization check. Ordinary accounts receive 403; anonymous requests receive 401. Privileged APIs also check roles independently of navigation. Developers cannot use the administrator endpoints or the older permanent-inventory grant endpoint.

The session cookie's existing `/api` path includes the protected application. Same-origin routing preserves secure cookies, CSRF and allowed-origin checks without introducing a public development server or exposing API/PostgreSQL ports. NGINX keeps the public worker prohibition and gives only the protected application the worker policy needed by the existing simulator. Protected resources use `no-store`; real-path containment and a resource-extension allowlist exclude server files, source maps and secrets. Hosted startup refuses a missing protected build rather than displaying unusable navigation.

The backend defaults to `CONTROL_APP_DIR=dist-control` locally; the image uses `/app/dist-control`. Build this directory before starting a compiled local protected UI. The full local application also retains its previous restricted Studio navigation. Neither address authorizes an ordinary player.

One additive migration extends invitation metadata with stable public IDs, revocation, reasons and per-actor request identifiers. No existing player, inventory, deck, match or Studio schema is rewritten. Back up and rehearse before applying it; use the [operator procedure](V1.5-OPERATIONS.md). If an account is reactivated after session revocation, reload the game and sign in again.

## Owner acceptance after installation

1. Log in with the existing owner account. Verify the same Mythical collection and decks, then open Administration.
2. Inspect a designated tester, grant an approved test card with a reason, and review the same grant. Confirm the quantity increases once and history contains its reason.
3. Generate an invitation, privately retain its code, use/revoke it, and confirm revocation prevents another redemption. Never include a live code in screenshots or Git.
4. Create a private test creature in Studio, upload temporary artwork, configure supported mechanics, inspect its full-bleed face and save it. Run a sandbox and small simulation, reload, then download a private backup. Confirm ordinary catalog/ownership/statistics did not change.
5. Use an ordinary account and a developer account to verify the separate access boundaries. Log out in another same-origin tab; the protected application clears private UI and returns to login.
6. Play a complete normal match at 100% zoom using the [viewport acceptance guide](GAMEPLAY-VIEWPORT.md).

Actual Ubuntu/Docker/HTTPS installation and physical-device/owner acceptance remain for the owner and Ember. Local PostgreSQL-backed browser evidence and screenshots are in the [validation report](V1.5-VALIDATION.md).
