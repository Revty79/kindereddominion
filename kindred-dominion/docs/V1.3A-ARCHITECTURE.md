# V1.3A implementation and compatibility

The stage extends the existing React/TypeScript/Vite application and deterministic game engine. It introduces no account, external AI, database server, paid service or final card/artwork dependency.

## Module boundaries

| Module | Responsibility |
|---|---|
| `engine/advanced-types.ts` | Structured numeric/condition/passive/scoring definitions, immutable participants, power changes and historical state |
| `engine/evaluation.ts` | Pure bounded expressions, shared target filters, conditions and acyclic power layers; mutation-sensitive memoization |
| `engine/advanced-runtime.ts` | Successful-change reactions, captured history, transition truth, causal-chain protection and death stabilization |
| `engine/game.ts` | The existing resolver/action path, extended with gated advanced hooks, frozen simultaneous inputs, captured sources and atomic advanced-fault rollback |
| `engine/scoring.ts` | Authoritative power entry point, original Classic/Domination rules and pure separate card bonuses |
| `engine/registry.ts` / `advanced-validation.ts` | Actual supported mechanics, readable descriptions, bounded DSL validation and rejection of unsupported dependencies |
| `studio/TargetEditor.tsx` / `MechanicsFields.tsx` | Forms for target filters, recursive conditions/expressions and continuous/scaling/scoring entries |
| `ui/PowerDetails.tsx` / `ExecutableRules.tsx` | Shared inspectable effective power, protection, card rules and separate score details |
| `content/laboratory.ts` | Lazy development fixture construction: 45 cards, four decks, 30 prepared scenarios |
| `content/bundled.ts` | Adds missing lab versions/scenarios without overwriting owner entities or activating them |
| `replay/record.ts` / `content/transfer.ts` | Explicit old/new engine compatibility, immutable reconstruction and validated atomic imports |
| `scripts/validate-v1.3a.mjs` | Reproducible preserved-library comparison and advanced stress runs |
| `scripts/verify-build.mjs` | Actual compiled image checksums, source-master exclusion and player-only fixture/chunk exclusion |

The actual engine remains shared by normal play, AI candidate evaluation, previews, sandbox, worker simulation and replay. No simplified mechanics model was introduced. Existing one-ply AI policy is unchanged; it now observes authoritative effective power and final scores through the shared functions.

## Preservation strategy

Baseline: `96d85f74a0b37664c1a7cc68ab6cd465c2f33a9f`, with recovery tags and a verified complete-history bundle recorded in [baseline receipt](V1.3A-BASELINE.md).

Original source definitions/decks, `content/founding.ts`, published artwork content, original asset bytes/manifest and prior balance evidence are preserved. Existing generated descriptions retain their original wording, so the complete serialized 150-card comparison library stays identical, including text and metadata.

Libraries without advanced mechanics retain the original state/event/signature path. Advanced hooks activate for explicitly advanced definitions. No new history block or public events are added to legacy games. Golden original matches and the full preserved 4,720-match seed/configuration comparison check this behavior.

Active games retain their own immutable library/artwork. Existing working drafts and selected versions are not replaced by adding bundled lab content. If the new bundle cannot be saved, the already loaded valid workspace remains available for backup/use with an explicit storage error. Stale-tab revision checks and current/previous atomic IndexedDB transactions remain in place.

## Explicit versions

| Data | Compatibility contract |
|---|---|
| Legacy content | Schema 1, engine 1.1.0; unchanged originals/comparison libraries |
| Advanced content | Schema 2, engine 1.3.0; saving/importing advanced cards upgrades only the working draft |
| Game state | Existing version 1 envelope; advanced games add a version-2 mechanics block |
| Workspace / transfer / replay envelope | Schema 1 retained with explicit supported engine declarations and full nested validation |
| Mixed backups | Declare engine 1.3.0 if any included version/scenario/replay/report needs it, even when the working draft is old |
| Artwork publication | Existing package/asset schemas, with the matching content schema and engine preserved |

Legacy replay interpretation rejects advanced definitions. Unknown engine/schema versions or divergent signatures fail explicitly. Recorded definitions, initial state, actions, results and artwork are never silently replaced by the latest library. New numerical history is not fabricated for an old save.

## Power and event semantics

The full specification is [Master Card Mechanics](MASTER-CARD-MECHANICS.md). The key engineering choice is a fixed dependency order: intrinsic power → conditional protection → auras → pre-dynamic classification → scaling → effective power. There is no iterative passive fixed point. The evaluator fingerprints relevant mutable state when memoizing; external caching does not mutate gameplay state.

Multi-target numerical amounts and direct immunity decisions are captured before mutation. Existing ordered summoning destination behavior and special sacrifice/replacement ordering remain intact. A recalculation records one actual net effective transition per creature, with component deltas; it does not pretend arithmetic substeps were distinct battlefield states. Optional observers capture real resolver snapshots and remain outside match signatures.

Lifetime explicit permanent-modifier history and net effective-change reactions are distinct, avoiding self-feeding passive history. Threshold truth and first-change flags persist by lineage; per-event/turn/match counts and causal ancestry prevent repeated self-entry. Simultaneous destruction can produce further aura-loss deaths; stabilization completes before another voluntary action.

An advanced fault restores the pre-action state, halts with a diagnostic and no result, and leaves a readable board. Simulation faults/timeouts/invariants remain separate from competitive outcomes. Free Play does not disable universal safeguards.

## Production and artwork

Normal builds keep Studio as a lazy chunk and simulation in a worker. `VITE_STUDIO=0` excludes those controls/chunks and the lab fixtures from a clean build. Fixture definitions are constructed lazily so unused module initialization cannot leak them into player-only bundles. Existing owner-stored experiments are preserved, rather than deleted by switching build mode.

Runtime artwork remains in `public/assets/`, masters in `artwork-source/`, and published references remain portable/immutable. Compilation and `verify-build.mjs` check registered image integrity and ensure source masters are absent from client output. Both content schemas can use the existing approved publication/import pipeline. The browser tests exercise schema-2 publication with temporary artwork and an isolated repository import.

No mobile platform project or external host is added. A future wrapper can package the same relative static output. Physical mobile and commercial/artistic acceptance remain owner review; Chromium's touch-sized test is not a physical-device claim.

See [owner guide](V1.3A-OWNER-GUIDE.md) for design/testing actions and [validation report](V1.3A-VALIDATION.md) for final receipts, simulations and known limits. V1.3B, commercial card design, balancing and final illustration work remain outside this stage.
