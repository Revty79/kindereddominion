# V1.5G isolated content expansion rehearsal

The founding 150 definitions and original artwork remain unchanged in this repository. Disposable test content lives only in registered isolated PostgreSQL databases and ignored validation storage. It is not an approved expansion, Kindred, product or commercial policy.

The PostgreSQL integration suite publishes a temporary N031 with the existing Nature rules, a separate permanent expansion identity and retained founding IDs. The same content/configuration services validate a free expansion collection, a premium-classified collection (whose identity also remains freely available), a one-card guaranteed-new booster, a fixed additional-copy bundle, an achievement reward, a custom 15-card format and a temporary alternate-art entitlement. It verifies acquisition, shop pack history, quantities, concurrent objective claims, deck legality, actual match creation, isolated artwork purchase/equipment and source reconciliation. A separate temporary repository tree also exercises automatic seeding: a fully registered new publication is official but inactive until explicit activation, and existing publication channels remain immutable. The approved founding active catalog is restored after the test. Experimental identity/version records remain retained in the disposable database; nothing is deleted or reassigned.

Existing accumulated test revisions are respected by giving the disposable publication an appropriate later definition revision, while comparing all founding gameplay fingerprints against the original definitions. This does not change source mechanics or published production cards. New artwork uses fallback or the existing temporary `art-sprout` asset exclusively; no final illustration was generated.

A packaging defect was corrected: player builds formerly required exactly 150 cards and rejected any expansion. The shared guard now requires every original founding identity exactly once, with its permanent number, Kindred, gameplay identity and set unchanged. It permits additional validated published identities only with matching active reviewed registry entries. Missing, duplicated and reassigned founders remain rejected. Artwork approval, local-image rejection and immutable manifest checks are unchanged.

Additional Kindred support was exercised at the existing private Free Play engine boundary with an independent disposable creature. The engine accepts data-defined Kindreds and preserves invariants after an actual placement. Ordinary starter selection intentionally remains the five approved founding choices; this rehearsal does not authorize a sixth starter or invent its 30-card roster, gameplay identity, artwork or commercial terms.

## Repeatable repository publication

1. Author and validate in private Developer Studio. Assign reviewed permanent IDs in the data-only `src/content/collectible-registry.json`; do not reuse or replace an existing/retired entry. N031 is the first reserved Nature expansion number, not a new founding identity. This is reviewed content data, not a source-code mechanics change.
2. Keep every founding identity in the selected complete player content pack. Export an explicitly approved new content version and associated artwork using the existing portable publication pipeline. Keep original masters separately from optimized production WebP. Draft or browser-local artwork is not automatically published.
3. Validate and import on an isolated checkout:

```powershell
node scripts/import-content.mjs <APPROVED_PACKAGE.kindred.zip> --validate-only
node scripts/import-content.mjs <APPROVED_PACKAGE.kindred.zip>
node scripts/validate-assets.mjs
```

4. Review the registry/content/artwork diff, commit the data and assets together, and validate tracked assets. Publish to a registered isolated database first:

```powershell
npm run backend:build
node server-dist/cli.mjs seed --file=src/content/published/<CONTENT_ID>.json --activate
$env:VITE_PLAYER_CONTENT_ID='<CONTENT_ID>'
node scripts/build-player.mjs
```

The CLI requires the reviewed repository path and tracked file; ordinary publication requires registered permanent identities and production-approved artwork. The build packages portable references, fallback and approved runtime assets while excluding source masters and private Studio content. On hosted TEST the existing operator's configured `publishedContent` selection drives both player build and explicit seed/activation; no manual deployment is performed by this rehearsal.

5. Through protected Control, draft and validate collections, rarity, products, reward references and formats. Publish the shop before publishing economy documents that reference its booster/cosmetic rewards. Keep first-copy Gold access for all founders. Match and purchase snapshots retain old terms across publication/rollback.
6. Run the existing PostgreSQL/browser/asset validation and paired backup/isolated restoration before making content eligible. Keep old source masters, optimized revisions, content versions and registry assignments for archived matches. Runtime configuration rollback selects a new reviewed configuration version; it never rewrites settled receipts or old artwork.

The final G report records the isolated clean-checkout packaging receipt. Do not copy the disposable rehearsal content into the actual founding catalog.
